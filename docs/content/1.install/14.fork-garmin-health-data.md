# Fork note: Garmin Health Data (Coolify)

This fork adds a separate External Provider type **`garmin_health_data`** (“Garmin Health Data”) backed by a Python sidecar that wraps the PyPI [`garmin-health-data`](https://github.com/diegoscarabelli/garmin-health-data) package. It coexists with classic **Garmin** (nutrition / workout definitions); GHD owns deep wellness + FIT-backed activities and projects training-useful rows into Sparky’s existing product tables.

## Coolify / Docker

1. Point Coolify at your fork’s **`deploy`** branch (or equivalent) and build from this repo’s Dockerfiles — do not use upstream `codewithcj/*` images if you need this feature.
2. The **`sparkyfitness-ghd`** service is already in `docker/docker-compose.coolify.yml` / `docker/docker-compose.dev.yml`. It should:
   - Build from `docker/Dockerfile.ghd_microservice` (prod) or `.dev`.
   - Expose an internal-only HTTP port (default **8001**).
   - Mount a **persistent volume** at `/data` for per-user GHD SQLite warehouses and tokens (`/data/{sparky_user_id}/…`). Set Coolify `GHD_DATA_PATH` accordingly.
3. Set on **`sparkyfitness-server`**:
   - `GHD_MICROSERVICE_URL=http://sparkyfitness-ghd:8001` (default in compose).
4. After deploy, restart the backend so migration `20260821220000_garmin_health_data_provider.sql` applies and RLS reapplies. That seeds provider type `garmin_health_data` and creates `ghd_sync_runs`, `ghd_activity_map`, `ghd_history_import_jobs`, and `ghd_history_import_weeks`.
5. In the app: **Settings → External Providers** → add **Garmin Health Data** with Garmin email/password (strictly private; never shared via `share_external_providers`).

Classic Garmin can remain linked for nutrition / workout defs. Use **Fill history gaps** on the GHD card for multi-year backfill (chunked job); keep-alive `sync_frequency` stays separate.

For a field/table comparison, isolation rules, and live duplicate checks, see [15.fork-garmin-vs-ghd-data-model.md](./15.fork-garmin-vs-ghd-data-model.md).

## Notes

- Deep series stay in sidecar SQLite; Postgres only holds projected product rows plus the thin `ghd_*` provenance/job tables (Tier 1 owner-only).
- Bump the GHD PyPI pin deliberately when validating upstream extract/FIT fixes; do not reinvent extractors in Node.
- Do not commit Garmin credentials; use local/Coolify secrets only.
