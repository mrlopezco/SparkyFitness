# Fork note: Garmin Health Data (Coolify)

This fork uses **Garmin Health Data** (`provider_type` = `garmin_health_data`) as the **sole wearable Garmin sidecar**. Classic Connect (`sparkyfitness-garmin`) is **not** composed. Meals stay in the SparkyFitness diary.

## Coolify / Docker

1. Point Coolify at your fork’s **`deploy`** branch (or equivalent) and build from this repo’s Dockerfiles — do not use upstream `codewithcj/*` images if you need this feature.
2. The **`sparkyfitness-ghd`** service is in `docker/docker-compose.coolify.yml` / `docker/docker-compose.dev.yml`. It should:
   - Build from `docker/Dockerfile.ghd_microservice` (prod) or `.dev`.
   - Expose an internal-only HTTP port (default **8001**).
   - Mount a **persistent volume** at `/data` for per-user GHD SQLite warehouses and tokens (`/data/{sparky_user_id}/…`). Set Coolify `GHD_DATA_PATH` accordingly.
3. Set on **`sparkyfitness-server`**:
   - `GHD_MICROSERVICE_URL=http://sparkyfitness-ghd:8001` (default in compose).
4. After deploy, restart the backend so migrations apply (including `20260821220000_garmin_health_data_provider.sql` and the classic-vs-GHD dedupe cleanup) and RLS reapplies.
5. In the app: **Settings → External Providers** → add **Garmin Health Data** with Garmin email/password (strictly private; never shared via `share_external_providers`). Link sets `sync_frequency=hourly` so keep-alive cron runs.

Header **Sync all active providers** and the server hourly keep-alive cron both cover `garmin_health_data` (same pattern as other wearables). Use **Fill history gaps** on the GHD card for multi-year backfill; keep-alive stays separate.

Classic Garmin Connect is not required for Training or diary wellness.

For a field/table comparison and ownership rules, see [15.fork-garmin-vs-ghd-data-model.md](./15.fork-garmin-vs-ghd-data-model.md).

## Notes

- Deep series stay in sidecar SQLite; Postgres only holds projected product rows plus the thin `ghd_*` provenance/job tables (Tier 1 owner-only).
- Bump the GHD PyPI pin deliberately when validating upstream extract/FIT fixes; do not reinvent extractors in Node.
- Do not commit Garmin credentials; use local/Coolify secrets only.
- `SparkyFitnessGarmin/` source remains in the repo for upstream merge safety but is not started by compose.
