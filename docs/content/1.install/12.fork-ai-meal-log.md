# Fork note: Quick AI Meal Log (Coolify)

This fork adds a diary **Quick AI Meal Log** button that parses natural-language meals with your configured AI provider, then resolves nutrition from Sparky’s food database cascade (internal → configured providers → OpenFoodFacts → AI estimate last). The same lookup powers **Describe with AI** on the Add Custom Food form.

## Coolify / Docker

No new Compose environment variables are required for Gemini.

1. Point Coolify at your fork’s **`deploy`** branch (or equivalent) and use `docker/docker-compose.coolify.yml` (builds from `docker/Dockerfile.frontend` + `docker/Dockerfile.backend`; named volumes; domain → `sparkyfitness-frontend:80`). Do not use upstream `codewithcj/*` images if you need this feature. See `docker/coolify_deployments.md`.
2. In the running app: **Settings → AI Service** → add a **Google** service with your Gemini API key (defaults to `gemini-2.5-flash`; `gemini-3.1-flash-lite` is a good cost-efficient pick). Enable **Active**.
3. Enable food data providers under **Settings → External Providers**:
   - Prefer **USDA FoodData Central** (free API key from [fdc.nal.usda.gov](https://fdc.nal.usda.gov/api-guide.html)) for accurate whole foods.
   - OpenFoodFacts is used as a free fallback, but anonymous requests can return **HTTP 503** under load — if that happens, meal log falls back to `ai_estimate` until USDA (or another provider) is configured.
4. Set `ALLOW_PRIVATE_NETWORK_AI=true` in Coolify env **only** if non-admin users must call private/custom AI URLs (Ollama on a LAN). Default `false` is the SSRF-safe setting.

Gemini keys stay encrypted in `ai_service_settings` (database), not in Coolify secrets.
