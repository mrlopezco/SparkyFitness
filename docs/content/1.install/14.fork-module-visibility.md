# Fork note: Module Visibility Toggles

This fork adds **Settings → Module Visibility** so each user can hide major app modules from navigation and deep links without deleting upstream code.

## What it does

- Per-user preferences in `user_module_preferences` (owner-only JSONB map)
- Known modules (defaults):
  - **Exercises** — on by default; hides `/exercises`, `/workout-playback`, and Add-sheet Exercises
  - **Medications** — on by default; hides `/medications` and related nav/Add entries
  - **Training Plan** — off by default; Settings toggle only (feature not implemented yet)
- Hide depth: **nav + route gates only**. Diary exercise tiles, Reports sections, chatbot tools, and backend APIs remain available.

## Coolify / Docker

No new Compose environment variables.

1. Deploy from this fork’s **`deploy`** branch (or equivalent) and build from fork images — not upstream `codewithcj/*` if you need this feature.
2. Restart the backend once so migration `20260820200000_create_user_module_preferences.sql` applies.
3. In the app: **Settings → Profile & Account → Module Visibility** — turn off Exercises and/or Medications.

## Mobile

Web-only for this MVP. The Expo app does not read these toggles yet.

## Upstream merge safety

Logic lives in new files (`forkModules` config, module-preference API/service, Settings section, `ModuleRoute`). Upstream touch points are thin: one route mount, Settings accordion item, MainLayout filters, and `App.tsx` route wraps.
