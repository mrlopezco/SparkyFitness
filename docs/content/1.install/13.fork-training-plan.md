# Fork note: Training Plan (Coolify)

This fork adds a **Training Plan** module: date-based plans with goals and fixed commitments (e.g. soccer, hikes), an AI propose → review → confirm planner, a **Training plan** workspace (month calendar + coach chat), code-built athlete snapshots for token-efficient AI context, Garmin adherence matching after activity sync, athlete execution replies, and JSON import/export.

It also adds an **AI coach** that can discuss the plan and propose adjustments (still human-confirmed), and **fitness snapshots** — periodic time trials that keep prescribed paces anchored to measured fitness.

## Coolify / Docker

No new Compose environment variables are required.

1. Point Coolify at your fork’s **`deploy`** branch (or equivalent) and build from `docker/Dockerfile.frontend` + `docker/Dockerfile.backend` — do not use upstream `codewithcj/*` images if you need this feature.
2. After deploy, restart the backend so migrations `20260820210000_add_training_plan_schema.sql`, `20260820220000_training_fitness_tests_and_skip_reason.sql`, and `20260821153000_training_athlete_execution_score.sql` apply and RLS reapplies.
3. In the running app: **Settings → Module Visibility → Training Plan** → enable (off by default).
4. Configure **Settings → AI Service** the same way as Quick AI Meal Log (Gemini or other provider). The planner, the plan adjuster, the coach, and session AI review all use the user’s active AI service.
5. Link Garmin under **Settings → External Providers** so planned sessions can auto-match logged activities after sync, and so race predictions and lactate threshold flow into the athlete snapshot.

## Training plan workspace

- Tabs: Overview, Goals & commitments, **Training plan**, **Coach Chats**, Fitness tests.
- Overview: multiple plans allowed, **one active at a time**; New plan opens a dialog; Active plan details shows snapshot/KPIs (AI coach lives on Training plan / Coach Chats).
- The Training plan tab has Plan with AI, then a full-width month calendar (future days colored by workout type; past by completed/partial/skipped) and a full-width workout list below.
- **Generate plan** must cover every day from `start_date` through `target_date` (rest days included), with titles, instructions, pace/HR for runs, and optional mid-block fitness tests. Missing prescription fields are enriched from the athlete snapshot when the model omits them.
- Coach Chats is a dedicated chat UI (history on the left, thread in the middle). The coach can still propose plan adjustments; confirm happens on the Training plan tab.

## Coach

- A coach conversation is scoped to one plan (`training_coach_sessions`), with its transcript in `training_coach_messages` and a rolling summary in `training_coach_session_summaries`. Closing a session writes the summary; the next session reads that instead of the whole transcript.
- Durable facts (a recurring night shift, an old injury, a preference) live in `training_coach_memories`. The coach proposes them, the server applies them, and the athlete can list or delete them from the API.
- The coach can schedule a fitness test, prompt a skip reason, and call `propose_plan_adjustment` / `propose_full_plan`. Those return a proposal the athlete must confirm — the coach never writes sessions directly.

## Fitness snapshots

- `training_fitness_tests` holds scheduled and reported time trials (5K, 10K, Cooper 12-minute, mile effort, easy aerobic check, or custom).
- A reported result feeds the athlete snapshot, which is what re-anchors the easy / tempo / threshold paces the planner prescribes.
- Paces are derived in code (`services/trainingRunningScience.ts`) from Garmin race predictions using Riegel projection and standard percentage-of-race-pace zones, not by asking the AI to invent them.

## Weekly check-in cron

A daily job at **07:00 server time** scans every active plan and opens a coach session for athletes who have drifted:

- no coach check-in in the last 7 days, **or**
- more than 2 planned sessions in the last week never logged, **or**
- no fitness test in the last 28 days.

It skips anyone who already has an open coach session, rebuilds the athlete snapshot first, and can schedule a 5K time trial alongside the check-in. The scan never throws: a failure for one athlete is logged and the scan continues.

## Notes

- Athlete context for the AI is built in code (`training_athlete_snapshots`), not by dumping raw Garmin history into the prompt.
- The snapshot also carries compact wearable enrichment from existing `daily_health_metrics` and `sleep_entries` (independent of any GHD sidecar): readiness (training readiness, acute/chronic load, ACWR, recovery hours, RHR, body battery, stress, overnight HRV), a short readiness trend (≤7 days), sleep averages, and marathon race prediction alongside shorter distances. Same-day rows prefer `source_provider` / `source` `garmin_health_data` over `garmin`. Session AI review can include matched activity and that day's readiness when available.
- Existing weekly **Workout Plans** (Mon–Sun templates) are unchanged; Training Plan is a separate date-keyed domain.
- All training endpoints require the `can_manage_diary` permission, so a delegate with diary access can coach on someone else's behalf.
