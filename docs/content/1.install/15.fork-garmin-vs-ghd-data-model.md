# Fork note: Garmin vs Garmin Health Data — data model

This document describes how **Garmin Health Data** (`garmin_health_data`) writes into Sparky Postgres on this fork, and how classic Garmin (`garmin`) is treated when both exist.

Ops setup: [14.fork-garmin-health-data.md](./14.fork-garmin-health-data.md).

---

## 1. Recommended mode (this fork)

| Role | Owner |
|---|---|
| Wearable wellness + activities | **GHD only** (`sparkyfitness-ghd`) |
| Meals / nutrition | **SparkyFitness diary** (not Garmin) |
| Classic Connect sidecar | **Not deployed** in compose |

When GHD is linked and active, classic sync skips wellness and activity writes (defense in depth). A one-time migration removes classic parallel rows where a GHD twin exists and deactivates classic providers for users who have active GHD.

---

## 2. Mental model

| Layer | Classic Garmin | Garmin Health Data (GHD) |
|---|---|---|
| Provider type | `garmin` | `garmin_health_data` |
| Sidecar | `SparkyFitnessGarmin/` (not composed) | `sparkyfitness-ghd` |
| Deep archive | Not kept | Per-user SQLite under `/data/{user_id}/` |
| Postgres role | Legacy / optional | Project training-useful subset into product tables |

**Ownership rule:** one user-facing fact per calendar day / activity — GHD wins over classic. Source tags still isolate rows; consumers and cleanup prefer a single owner.

---

## 3. Shared product tables (GHD writes)

### 3.1 `daily_health_metrics`

**Uniqueness:** `UNIQUE (user_id, entry_date, source_provider)`

GHD projects steps, floors, intensity minutes, RHR, stress, body battery, VO₂, training load, readiness, plus **activity-rolled** `active_calories` / `bmr_calories` / `total_distance_meters` when SQLite activities have those fields.

Reads (`getDailyHealthMetrics`) use `DISTINCT ON (entry_date)` ranked GHD → classic → other.

### 3.2 `health_metric_samples`

**Uniqueness:** `UNIQUE (user_id, metric, entry_date, source_provider)`

Metrics: heart_rate, stress, body_battery, hrv, respiration, spo2.

### 3.3 `sleep_entries`

Tagged with `source`. GHD projects stages and overnight HRV / SpO₂ / RHR when present. Sleep science and diary sleep list drop classic twins when GHD exists for the same night.

### 3.4 `exercise_entries`

`source = 'garmin_health_data'`, `source_id` = Garmin activity id. Local wall-clock dates via `timezone_offset_hours` in `SparkyFitnessGhd/projection.py`.

**Distance unit:** `exercise_entries.distance` is **kilometers** (same as Diary / Training `distance_km`). Sidecar emits `distance_km`; the projector stores that value as-is (not metres).

Dedupe: `ghd_activity_map` + skip if either provider already has the same `source_id`. Classic `activityAlreadyImported` also checks the map.

### 3.5 `food_entries`

GHD **never** writes nutrition.

---

## 4. Guarantees

1. Different source tags — writers do not overwrite each other’s rows.
2. When GHD is active, classic sync does not write wellness/activities.
3. GHD activity map + cross-provider `source_id` skip keep activity imports idempotent.
4. Cleanup migration removes historical classic twins for users with GHD data.

## 5. Verification SQL

```sql
-- Row counts by source
SELECT 'daily_health_metrics' AS tbl, source_provider::text, COUNT(*)
FROM daily_health_metrics
WHERE source_provider IN ('garmin','garmin_health_data') GROUP BY 2
UNION ALL
SELECT 'sleep_entries', source, COUNT(*) FROM sleep_entries
WHERE source IN ('garmin','garmin_health_data') GROUP BY 2
UNION ALL
SELECT 'exercise_entries', source, COUNT(*) FROM exercise_entries
WHERE source IN ('garmin','garmin_health_data') GROUP BY 2;

-- Overlaps should be 0 after cleanup + GHD-only sync
SELECT COUNT(*) AS overlapping_daily_days
FROM daily_health_metrics d1
JOIN daily_health_metrics d2
  ON d1.user_id = d2.user_id AND d1.entry_date = d2.entry_date
 AND d1.source_provider = 'garmin_health_data'
 AND d2.source_provider = 'garmin';

SELECT COUNT(*) AS same_source_id_pairs
FROM exercise_entries g
JOIN exercise_entries c
  ON g.user_id = c.user_id AND g.source_id = c.source_id
WHERE g.source = 'garmin_health_data' AND c.source = 'garmin';
```
